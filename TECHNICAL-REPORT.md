## 3. Администратор в исходниках `5ee5e46`

Публичной функции `claimAdminSeat` нет. Первый вошедший пользователь не назначает себя сам.

`resolveAdminAccess` делает следующее:

1. Если процесс продовый (`GROK_PROJECT_ID` или `VERCEL_ENV=production`) и авторизация выключена, нет `GROK_AUTH_CLIENT_ID` / `GROK_AUTH_CLIENT_SECRET`, или идентификатор клиента равен `grok_preview`, запрос получает `Unauthorized`.
2. Идентификатор `dev-user` отклоняется всегда.
3. Пустой `KLYVONA_ADMIN_EMAILS` закрывает всех.
4. Почта читается из таблицы `user` по идентификатору сессии. Адрес из браузера не принимается.
5. Нужны `emailVerified = true` и точное совпадение со списком.
6. Только тогда сервер пишет строку в `staff_members`. Сама строка права не даёт.

Четыре админ-функции (`getAdminAccess`, `getDashboard`, `getClientProfile`, `updateClientOps`) стоят за `authMiddleware`.

Онбординг в `staff_members` не пишет.

В проде без `DATABASE_URL` код не переходит на память. Превью без `GROK_PROJECT_ID` и без `VERCEL_ENV=production` может использовать PGLite. Такая память не переживает перезапуск процесса.

Эти правила есть в `5ee5e46`. На живом сайте их нет: сайт собран в 14:49 UTC, до этого коммита.

## 6. Что нужно задать перед боевым приёмом заявок

Значения ниже нельзя класть в репозиторий. Уточнение от проверки экрана Publish > Secrets, 11 октября 2026, около 15:49 UTC, записано в разделе 8. Коротко:

1. `DATABASE_URL` подставляет Grok при публикации. Вручную строку базы не вводить.
2. `KLYVONA_ADMIN_EMAILS` добавляется вручную: подтверждённые адреса Google через запятую.
3. `GROK_AUTH_CLIENT_ID`, `GROK_AUTH_CLIENT_SECRET`, `BETTER_AUTH_SECRET` и `BETTER_AUTH_URL` подставляет платформа. Не копировать секрет превью.
4. `MAKE_WEBHOOK_URL` — только когда уведомление Make нужно. Сейчас на сайте адрес не задан.
5. Секреты Meta и TikTok — только отдельным включением OAuth. Сейчас его нет.

## 8. Экран Publish > Secrets

Проверено по коду этого репозитория и по конфигурации `.grok/app-env.json`. Сам экран Grok отсюда не открывался. Значения секретов не снимались и здесь не записаны. Ничего не публиковалось и база не создавалась.

На экране были только:

- `VITE_NEON_AUTH_URL`
- `NEON_AUTH_BASE_URL`

Эти два имени в исходниках KLYVONA Connect не читаются. Это Neon Auth, не строка Postgres. Вставлять в них адрес базы или выдуманные значения не нужно. Оставлять пустыми.

| Вопрос | Результат |
|---|---|
| Neon Postgres уже прикреплён к живому сайту | **UNVERIFIED** |
| `DATABASE_URL` вводит пользователь | **Нет.** Его подставляет Grok |
| `KLYVONA_ADMIN_EMAILS` добавлять в Secrets | **Да, вручную** |
| Ключи входа вводить вручную | **Нет.** Их подставляет Grok |
| Другие секреты перед Update | **Не нужны** |

Почему база не вводится руками. В `.grok/app-env.json` стоит `"deploy": { "database": true }`. Есть `migrations/*.sql` и вход сотрудника. Платформа при публикации сама создаёт Neon и записывает серверный `DATABASE_URL`. Эта переменная не должна появляться среди двух полей Neon Auth.

Почему присоединение Neon к текущему сайту не подтверждено. Живая сборка от 14:49 UTC при пустом `DATABASE_URL` ещё умеет писать в память. Заявка `KV-J32PC5` поэтому не доказывает постоянную базу.

Что ввести перед Update, и только это:

1. Не заполнять `VITE_NEON_AUTH_URL` и `NEON_AUTH_BASE_URL`.
2. Добавить секрет с именем точно `KLYVONA_ADMIN_EMAILS`. Значение — адрес Google, которым входят в `/admin`. Несколько адресов через запятую, без пробелов. Не называть переменную `VITE_KLYVONA_ADMIN_EMAILS`: сервер читает имя без этого префикса.
3. Не добавлять `DATABASE_URL`, `GROK_AUTH_CLIENT_ID`, `GROK_AUTH_CLIENT_SECRET`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `MAKE_WEBHOOK_URL` и ключи Facebook, Instagram, TikTok.
4. Если своё имя переменной добавить нельзя, Update не нажимать: без списка администраторов управление останется закрытым.

Вход в админку после публикации — тем же аккаунтом Google. Почта должна быть подтверждена. Аккаунт X для списка не подходит: его почта не считается подтверждённой.

Код этой версии уже в коммите `5ee5e46` и входит в текущую ветку `main`. Этот раздел только фиксирует результат проверки. Он не меняет приложение и не выкладывает сайт.
